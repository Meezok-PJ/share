Module 01: Getting Started & Virtual Machine Lab Setup

A zero-to-hero guide on setting up a virtualized Linux lab environment using VMware, VirtualBox, or Proxmox, installing Ubuntu Server and Fedora, configuring network modes, and securing first-boot access.

⚠️
Educational Sandbox Notice
Always perform your Linux administration, package installations, and disk modifications inside an isolated Virtual Machine (VM). Never execute destructive formatting or root system modifications directly on your primary host machine without virtualization guardrails.

1. Choosing Your Hypervisor

A Type-2 hypervisor runs as an application on your existing Windows/macOS/Linux operating system, allowing you to run multiple isolated guest Linux environments simultaneously:

Virtualization Hypervisor Architecture
1. VMware Workstation / Player

Industry-standard desktop hypervisor. High-performance 3D graphics, seamless host-guest networking, and stable NAT bridging.

2. Oracle VirtualBox

Free and open-source cross-platform hypervisor. Excellent for lightweight CLI servers, snapshot branches, and portable OVA appliances.

3. Proxmox VE (Type-1)

Bare-metal enterprise hypervisor for dedicated homelab servers. Web UI, LXC containers, KVM virtual machines, and ZFS storage pools.

2. VM Hardware Specifications for Ubuntu Server

When provisioning your first headless Ubuntu Server 24.04/25.04 LTS virtual machine, configure these baseline hardware parameters:

Resource Minimum Spec Recommended Homelab Spec Notes
vCPU Cores 1 Core 2 - 4 Cores Supports parallel container builds and background compilation.
RAM 2 GB 4 GB - 8 GB Essential if running Docker Compose stacks (Code-Server, Pi-hole, databases).
Virtual Disk 25 GB (Dynamic) 40 GB - 60 GB Dynamically allocated disk consumes storage only as files are written.
Network Mode NAT Bridged Adapter Bridged assigns a real LAN IP on your home router for easy SSH from any device.

3. Step-by-Step Ubuntu Server Installation Walkthrough

Step 1: Installer Language and Base Profile

Boot the VM and select Try or Install Ubuntu Server. Choose your keyboard layout and select the default base installation profile (do not install minimized if you are a beginner, as standard includes curl, git, and diagnostic tools).

Figure 3: Ubuntu Server installer language selection and network DHCP detection.

Step 2: Network Configuration (DHCP vs Static)

By default, the installer queries your hypervisor's DHCP server for an IPv4 address. Note down the IP address assigned (e.g. 192.168.100.50 or 192.168.3.67).

Figure 4: Verifying DHCP network interface configuration and proxy settings.

Step 3: Guided Partitioning and LVM Setup

Select Use an entire disk and check Set up this disk as an LVM group. This creates an ext4 root partition managed under LVM, allowing you to expand volume sizes in the future without reformatting.

Figure 5: Confirming guided disk partitioning and LVM filesystem allocation.

Step 4: User Profile & OpenSSH Server Installation

Enter your server hostname (e.g. homelab-server), your administrative username (e.g. meezok), and a strong passphrase. On the next screen, check [X] Install OpenSSH Server — this is essential for connecting remotely over terminal.

Figure 6: Profile setup and OpenSSH daemon activation.

4. First-Boot Checklist & Baseline Security

Once installation finishes, reboot the VM and log in via your host terminal using SSH:

# Connect to your newly created VM from your host terminal
ssh meezok@192.168.3.67

# 1. Update package repository indexes and upgrade existing packages
sudo apt update && sudo apt full-upgrade -y

# 2. Install essential system diagnostic and admin packages
sudo apt install -y curl wget git htop tmux ufw net-tools build-essential

# 3. Enable the Uncomplicated Firewall (UFW) and allow SSH
sudo ufw allow 22/tcp
sudo ufw enable
sudo ufw status verbose
Module 01 Lab Verification Milestone

You now have a fully functional, headless Ubuntu Server Linux VM running with OpenSSH server and firewall enabled. You are ready to move to Module 02 to master shells, prompts, and the modern CLI toolkit!
