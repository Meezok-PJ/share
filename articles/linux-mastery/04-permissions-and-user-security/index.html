Module 04: User Administration, Permissions & Sudoers

⚠️
Sandbox Environment Warning
Execute all commands and scripts strictly inside an isolated Virtual Machine sandbox. Never perform bulk permission changes, system removals, or daemon restarts on unbacked host environments.

Comprehensive guide to Linux user and group creation, account properties, 3x3 permission matrices (octal vs symbolic), SUID/SGID/Sticky bits, and sudoers security.

1. User & Group Lifecycle Management

Linux manages account metadata in /etc/passwd (user registry), /etc/shadow (hashed passwords), and /etc/group (group memberships).

# Create a new user with home directory and bash shell
sudo useradd -m -s /bin/bash developer1

# Set user password
sudo passwd developer1

# Create organizational groups
sudo groupadd DevOps
sudo groupadd SecOps

# Assign user to multiple supplementary groups
sudo usermod -aG DevOps,SecOps,docker developer1

# Assign multiple users to group at once
sudo gpasswd -M dev1,dev2,dev3 DevOps

# Inspect user and group IDs
id developer1
getent group DevOps

2. The 3x3 Linux Permission Model

3x3 Permission Triad (rwxr-xr--)
User (Owner): rwx (7)

Read (4) + Write (2) + Execute (1) = 7. Full file control for file creator.

Group: r-x (5)

Read (4) + Execute (1) = 5. Shared team permissions for assigned group.

Others (World): r-- (4)

Read (4) only = 4. Read access for any other system user.

Figure 4: Inspecting file permissions and owner/group mappings with ls -l.

Octal (Numerical) vs. Symbolic Modes

# Octal absolute mode: Owner rwx (7), Group r-x (5), Others none (0)
chmod 750 deploy_script.sh

# Symbolic mode: Add execute for all users
chmod a+x run_app.sh

# Symbolic mode: Add read/write for user and group only
chmod ug=rw project_data.csv
Figure 5: Changing permissions using octal numerical values (e.g. chmod 555 firstfile).
Figure 6: Changing permissions using symbolic characters (e.g. chmod a+rwx firstfile).

3. Special Permissions: SUID, SGID, and Sticky Bit

Special Bit Numeric Value Applied to Behavior & Purpose
SUID (SetUID) 4000 Executables Executes binary with the privileges of the file owner (e.g. /usr/bin/passwd runs as root).
SGID (SetGID) 2000 Directories New files created inside inherit the parent directory's group automatically.
Sticky Bit 1000 Shared Dirs Only file owners can delete or rename their own files (used in /tmp).

4. Sudoers Security & Least Privilege

The Golden Rule: Never Edit /etc/sudoers Directly

Always run sudo visudo. It opens a locked editor and checks syntax upon saving, preventing accidental syntax errors that lock administrators out of root privileges.

# Grant developer passwordless restart for Nginx only
developer1 ALL=(ALL) NOPASSWD: /usr/bin/systemctl restart nginx

# Allow DevOps group full sudo access
%DevOps ALL=(ALL:ALL) ALL
